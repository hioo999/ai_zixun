1. 小米发布开源全模态模型 MiMo-V2.6 系列，登顶开放权重智能指数

小米 MiMo 官方 / Hugging Face CEO / Artificial Analysis

小米正式发布并开源 MiMo-V2.6 Pro 与 Flash 两款原生全模态模型，通过规模化强化学习训练。MiMo-V2.6-Pro 在 Artificial Analysis Intelligence Index 得分 46，超越前代 V2.5-Pro 的 26 分，为当前开放权重模型最高分；在多数 Agent 基准上与 Claude Opus 5、GPT-5.6 Sol 表现相当，Code Arena WebDev 榜以 1628 分位列开源权重第 3（MIT 许可）。官方称这是探索 RSI（递归自我改进）路径的关键一步。

启示

开源模型与闭源前沿的差距正在以季度为单位快速收窄——46 分已逼近闭源第一梯队，且采用 MIT 许可意味着商用无阻。对于做 AI 应用层的创业者，这意味着可以立即评估将 MiMo-V2.6-Pro 纳入技术栈，在编码、computer use、3D 推理等场景替代部分闭源 API 调用，显著降低推理成本。同时应关注其全模态能力对现有产品交互形态的可能冲击。

2. 阶跃星辰 Step 5 Preview 评测出炉：智能指数 44 分，成本仅为同级 1/2.8

Artificial Analysis

阶跃星辰 Step 5 Preview 在 Artificial Analysis Intelligence Index 得 44 分，与 Kimi K3（max）持平，略低于 GLM-5.3（max）和 Qwen3.8 Max 的 45 分。关键亮点在于每任务成本约 $0.72，约为同级模型（约 $2.00）的 1/2.8。

启示

国产大模型在"智能水平接近前沿"的前提下，成本优势已形成结构性竞争力。对于需要大规模调用模型的生产型应用（如批量文档处理、Agent 工作流），每任务成本从 $2 降至 $0.72 意味着毛利率的直接改善。建议创业者在选型时建立"智能指数/成本"的性价比评估框架，而非单纯追逐最高分——Step 5 Preview 这类模型可能才是规模化落地的最优解。

3. NVIDIA 推出 Nemotron 3.5 Lightning：30B MoE 专攻 Agent 高频执行调用

OpenRouter

NVIDIA 发布 Nemotron 3.5 Lightning，一款 30B 总参数、约 3B 激活参数的混合专家开源权重模型，定位于工具调用、编码等高频、边界清晰的 Agent 执行步骤。它与负责复杂推理的 Nemotron 3 Ultra（550B 总参数、55B 激活）形成明确分工。

启示

这代表了一种重要的 Agent 架构范式——"大模型做规划、小模型做执行"的级联模式正在被头部厂商产品化。3B 激活参数意味着极低的推理延迟和成本，非常适合承担 Agent 中大量重复的工具调用步骤。创业者在设计 Agent 系统时，应认真考虑将执行层从单一大型模型拆分为专用小模型，可大幅降低端到端延迟和 API 成本。OpenRouter 的解读文章值得细读。

4. 亚马逊封禁 Meta Muse 智能体代用户购物，AI Agent 生态冲突公开化

IT之家

亚马逊阻断了 Meta 个人 AI 智能体 Muse 代用户在其网站购物的访问权限，称从未许可该访问，并指 Muse 不表明身份、会采集保存用户账号凭证，带来隐私和安全隐患。双方争端升级。

启示

这是 AI Agent 与平台生态之间利益冲突的标志性事件。当 Agent 代表用户与第三方平台交互时，身份标识、数据边界、平台授权将成为核心矛盾。做 Agent 产品的创业者需立即审视：你的 Agent 访问第三方服务时是否明确标识自身身份？是否获得了平台方的明确授权？建议提前建立合规框架，包括用户授权链路、数据最小化采集、以及与传统平台的合作沟通机制——否则可能面临与 Muse 同样的封禁风险。

5. 不列颠哥伦比亚省起诉 OpenAI：AI 安全预警义务进入法律追责阶段

X @rohanpaul_ai

不列颠哥伦比亚省在加州起诉 OpenAI，指 flagged 的 ChatGPT 活动本应在 2026 年 2 月 10 日 Tumbler Ridge 枪击案前通报警方，该案致 8 人死亡、27 人受伤。这是首例政府因 AI 平台未履行安全预警义务而提起的诉讼。

启示

这标志着 AI 平台"发现风险信号后的主动报告义务"正从道德倡议转变为法律责任。对于任何提供面向公众的 AI 服务的企业，需要立即评估：你的系统是否有明确的风险 flagging 机制？flag 后的处置流程是否包含向执法机构报告的环节？建议法务与安全团队联合制定"AI 风险事件响应手册"，明确从检测到上报的完整链路和时限要求，避免因流程缺失而承担连带责任。
