1. OpenAI 发布 Decisions API：小决策场景的专用武器

OpenAI 官网动态

OpenAI 基于 GPT-6 Luna 正式推出 Decisions API，专为分类、路由、评分等"有界答案"问题设计，速度最高比通过 Responses API 调用同模型快 10 倍。这标志着 OpenAI 开始将"通用大模型"拆分为面向特定任务形态的专用接口。

启示

如果你的产品中存在大量"判断/分流/打分"类调用（如工单分类、内容审核、线索评分），现在是重新评估成本结构的好时机——专用 API 的延迟和成本优势可能让此前"用不起"的实时场景变得可行。建议本周内做一次 API 调用盘点，把有界决策类请求从通用对话接口迁移出来做 A/B 对比。同时注意：OpenAI 正在用接口层锁定高频低价值场景，创业公司若在此层做薄封装，护城河将被进一步压缩。

2. MiniMax 开源 M3.1 Flash：428B 总参数、23B 激活的 MoE 权重

X @MiniMax_AI

MiniMax 公开 M3.1 Flash 模型权重，总参数 428B、每 token 仅激活 23B，已在 Hugging Face 和 ModelScope 提供下载。这是又一家中国厂商加入"大参数、低激活"的 MoE 开源竞赛。

启示

23B 激活意味着推理成本接近中型模型，而 428B 总容量带来更强的知识储备——对预算敏感但需要较强能力的团队，这是值得立即压测的候选基座。建议重点验证三件事：中文长尾知识表现、微调后的指令遵循稳定性、以及在你自己的硬件上实际吞吐是否匹配官方宣称。开源权重也意味着可以私有化部署，对数据合规要求高的行业客户是加分项。

3. Claude 默认开启 auto mode：AI 产品"免确认"时代的分水岭

X @claudeai

下周起，Claude 的 Pro、Max、Team 套餐在网页、桌面和移动端将默认以 auto mode 运行——不再逐步请求用户批准，而由独立分类器自动拦截高风险操作，测试中拦截了 89% 的危险命令（手动批准仅 14%）。用户可随时切回手动模式。

启示

这是一次重要的产品信号：主流厂商判断"逐步确认"已成为体验瓶颈，转而用分类器做安全兜底。对做 Agent 产品的团队，这意味着两件事——第一，你的竞品交互标准正在从"确认弹窗"转向"静默执行+事后可审计"，用户体验预期会被拉高；第二，安全分类器的召回率成为核心竞争力，89% 的拦截率仍意味着约一成风险漏过，建议同步建设操作日志与回滚机制，而不是单纯依赖模型判断。

4. AI 攻防进入"Black October"：PHP2Shell 漏洞与自持续攻击智能体

404 Media / Ars Technica / Symantec（综合）

多条安全新闻指向同一趋势：AI 正在重塑攻防节奏。OpenAI 称其前沿模型先于攻击者发现 PHP2Shell 漏洞，但黑客仍在披露前获得四天窗口，公告后 2 小时内利用尝试从数千次飙升至数十万次；Symantec 则截获一个"Skynet 模式"智能体，可劫持无防护的 LLM 端点自主扫描、利用漏洞并安装挖矿程序，最多连续执行 10 万步，算力成本由被劫持模型的主人承担。

启示

两件事必须立刻做：一是排查你自己的模型端点是否暴露在公网且无鉴权——被劫持的不只是数据，还有你的算力账单；二是把"AI 辅助漏洞发现"纳入安全流程，攻防双方都在用 AI，响应窗口已从"天"压缩到"小时"。对安全赛道创业者，这是明确的需求爆发点：自动化补丁验证、Agent 行为审计、模型端点防护都是当前供给不足的方向。

5. Microsoft AI 的 MAI-DxO 登 Science：医疗诊断智能体的基准之战

Microsoft AI 官方博客

Microsoft AI 发布 Sequential Diagnosis Benchmark（SDBench）与 AI 诊断系统 MAI-DxO，论文登上 Science。这是大厂在垂直领域同时贡献"基准+系统"的典型打法，为医疗 AI 建立了可比较的评测坐标系。

启示

医疗 AI 的竞争正从"单点模型能力"转向"评测标准话语权"——谁定义基准，谁就定义什么叫"好"。对垂直行业创业者，这是一个可复用的策略：在你的细分领域（法律、金融、工业质检）率先构建公开基准，比单纯发布产品更容易建立行业地位。同时注意，SDBench 这类序列诊断基准强调多轮信息采集，与 Sierra 同日发布的语音实体采集基准 𝜏-Entity 呼应——"多轮交互中的细节准确性"正成为智能体落地的关键瓶颈，值得在产品设计中优先投入。
